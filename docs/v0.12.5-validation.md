# v0.12.5 validation

## Reproduced failure and correction

The release v0.12.4 was reproduced using a generated 11-second H.264 source with audio, a horizontal ticker texture and a vertical ticker texture. At 60 fps, ranges ending at 10.017 or 10.020 seconds require 602 frames (`ceil(duration * fps)`), but the native export produced 601 and failed verification. Longer fractional ranges at 10.025 and 10.030 seconds happened to pass.

The old command combined `-frames:v 602` with `-t 10.020`, and the filter graph also trimmed by duration. The new code uses an integer frame plan, trims by `end_frame`, emits constant-frame-rate timestamps, and does not impose a competing output time cutoff. A bounded source-tail allowance is preserved; export far beyond source duration still fails preflight. Final frame verification remains exact.

The intermediate video is MP4 so that the 60 fps time base remains exact through stream copying. MKV's millisecond-rounded timestamps had caused alternating timestamp intervals. Audio mixing uses the same planned frame duration and no longer truncates the copied video with a global `-t`.

## Tests performed

- 25 JavaScript tests passed.
- 22 Python tests passed.
- 11 range cases at 30 and 60 fps, including the exact 602/601 reproductions, one-frame exports, integer durations and non-zero range starts.
- Decoded-frame count, average frame rate, exact timestamp of every frame and full video/audio decode checked before and after audio mixing in regression fixtures.
- HTTP native-start, status polling, final download and FFprobe verification: downloaded file contains exactly 602 frames at 60 fps.
- Shared fixed-frame export tested with MP4/H.264, MOV/H.264, MP4/HEVC, MOV/HEVC, MP4/AV1, WebM/AV1 and WebM/VP9. WebM keeps its container's millisecond timestamp granularity; precise timestamp equality is asserted for intermediate MP4 and final MP4/MOV.
- Existing tests for long source EOF, truncated frames, sequential decoding, audio, native ticker pixels, pause/resume, cancellation and HTTP connection reuse passed.
- `npm run build` and Python compilation passed.

## Long export

- Generated 600-second, 1280×720, 30 fps source with audio ending 0.08 seconds later; source size 566,951,201 bytes.
- Exported at 60 fps, H.264 MP4, High quality, Fast preset, with horizontal and vertical ticker textures and audio.
- Completed in **156.54 seconds (2 minutes 37 seconds)**, including audio finalization and output frame-count verification. Source generation and browser upload time are excluded.
- Exactly **36,005 of 36,005 frames** verified. A subsequent complete output decode exited 0 with no decoding errors.
- Software libx264 on the test host; no AMD GPU. The ticker fixtures use colored textures, not a browser visual review of the user's actual fonts.
- This is a synthetic benchmark for this build, not a promised render time on the user's laptop or a comparison against Premiere/Resolve.

Reproduce with `python tests/benchmark_native.py`.

## Verification limits

These tests use generated media on a Linux host with FFmpeg 7.1.5 and software encoding. They do not test the user's original file, Windows browser, or AMD AMF driver. No real social-media account was used and no video was published. This export correction does not change account setup requirements or establish commercial launch readiness. A 30 fps source exported at 60 fps still repeats source pictures; it does not create new captured motion detail.
